# Changelog

All notable changes to `omp-memory`.

## 0.1.0 (2026-11-12)

First release, **beta**. The most recent changes are verified by tests only and there has been no third-party audit; use `--apply` only after a verified backup (`omp-memory backup --apply`).

- Command line `omp-memory`: `sources`, `banks`, `labels list|set|clear`, `import <scan|dry-run|import|verify|undo|doctor|project-map>`, `backup`, `restore-drill`,
  `export-hindsight`, `setup`, `doctor [--deep]`, `config show|set|unset|path|set-group|unset-group`. Python 3.10+, standard library only; the importer runs on Bun 1.4.4 or newer.
- Read-only by default: nothing adds `--apply`. `import import` is refused without it, `backup` and `export-hindsight` print a plan until `--apply`,
  `labels set` and `config set` write only their own small files (`0600`, atomic).
- The importer, the backup, restore-drill and Hindsight export scripts, and the standalone Python modules for banks, sources and labels are vendored
  byte for byte under `vendor/` (`scripts/sync-vendor.sh`, `scripts/vendor_manifest.txt`, `vendor/SOURCE.sha256`). A test fails when they drift from the source tree (named by `OMP_MEMORY_SOURCE_DIR`) or from the recorded checksums; `doctor` re-checks the checksums.
- The importer writes through the published `@oh-my-pi/pi-mnemopi` at exactly the version `omp --version` prints, found in omp's plugin directory or installed once by `omp-memory setup` into `~/.cache/omp-memory/lib/<version>` (it prints what it fetches, and refuses when npm has no such version). No omp source checkout is needed; there is no option to accept a different version. The importer's bank-id function and memory redaction are local copies, and `doctor` proves the bank-id function against your existing banks.
- Importer guards: refuses a bank another process has open (best effort: `lsof`, or `/proc` of your own user on Linux; checked before the plan, before each bank's write and before each undo deletion), a bank directory, database or side file that is a symbolic link, a library that is not omp's exact version, whose SQL (matched by structure) is not in the omp binary when that binary can be scanned, or that fails the **write test**, a bank whose schema (tables, full trigger definitions, extra triggers or views) differs; embeddings are made first and rows, annotations and embeddings of a bank are one transaction (a kill leaves nothing or everything; a digest of the native rows must not change); a lock file refuses a second `--apply` import or undo at the same time; run ids cannot be reused; `verify` compares row ids and provenance with the ledger and `undo --run` removes only rows that are provably the importer's and updates the ledger only for rows really gone; redaction plus a HOLD stage (also over file names, folders, tags and ids) whose held items need `--release-held`.
- The write test (`selftest.ts`) is what decides whether a library may be written through: through the loaded library, in a scratch bank under `/tmp`, the importer performs its exact write sequence (restore insert, annotation, embedding) and checks the row, its full-text entry, its annotations, its embedding row, `consolidated_at` and the trim exemption, then deletes the rows and checks that nothing is left. A failed step refuses the write and names it. `setup` and `doctor --deep` run it (`setup` also with the real embedding model), the first `import --apply` runs it when no passing result is cached, and plain `doctor` shows `OK` for a library only when it has passed (otherwise `WARN: not yet verified` or `FAIL`). `setup` removes what it installed when the library fails its checks. Run against omp 18.18.0 and 18.18.3 (`docs/compat.md`); `verify_versions.ts --suite <version>` checks another published version.
- Files that are not text (a NUL byte, or more than 2% undecodable characters) or longer than 1,000,000 characters (the redaction step's limit) are skipped and listed by key with the reason (`skippedBinary`, `skippedTooLarge`), not imported and not errors. `import scan` labels its numbers as an upper bound; `counts.wouldImport` of a dry run is the number the state file records.
- A first import on a machine without banks needs no backup (`backup --apply` says `nothing to back up`); banks an import of this tool created, while they hold only its rows, need none for a re-run; after an `undo` they count as new again for `--only-new-banks`. The dry run stays required.
- One exit-status convention everywhere: 0 success, 1 a refusal or failed check, 2 a usage or environment error, 3 an unexpected failure of the importer. `FOLDER` columns show paths under `~` even when `$HOME` is a symbolic link.
- `import --apply` refuses without a dry run of the same options (including the content of any file a flag names) and, when it writes into a bank that already holds anything of yours, a verified backup (`backup --apply`, re-read and recorded), both younger than 24 hours; `--no-backup` and `--skip-dry-run-check` are the explicit escapes. Which banks it reaches, and whether the plan still equals the dry run's (`planDigest`), is judged from a plan made when `--apply` runs. A flag given twice, or a value on a flag that takes none, is refused; the importer always starts in the plugin's own directory and gets absolute paths.
- Folder groups are generic: the first directory below your home, or the roots you name with `config set-group`, or a conf file you set; nothing about where your projects live is assumed. The Hindsight export has no defaults and is optional.
- Platforms: macOS and Linux. Run on macOS arm64 and in an Ubuntu 24.04 arm64 container as a non-root user (see `compat.json`); not run on Linux x64, musl or busybox userlands; Windows is not supported. `doctor` states which Bun, omp and library are used and, with `--deep`, checks the importer's SQL, schema and bank-id parity against your banks.
- Configuration (`banksDir`, `libDir`, `ledger`, `backupsDir`, `banksConf`, `stateFile`, `labelsFile`, `bun`, `ompBin`, `groups`) from flags, environment, a `0600` file, or defaults. A configuration file that is a link, not yours, group/other-writable or has an unknown key is refused.
- A skill (`skills/omp-memory`) that tells an agent when and how to use the command line safely.
- Tests: Python suite (scratch `HOME`, fake banks with the real schema, stand-in `bun`, a real second process holding a bank open, also through a symbolic link), the importer's own Bun tests run from the plugin copy against the npm package (every test file sets its own timeout), and the vendor drift tests; `scripts/smoke.sh` runs a whole cycle on synthetic data.
- `NOTICE` lists the code copied from omp (MIT, with its license text) and the npm packages, runtime and model that `omp-memory setup` downloads, with names, versions and licenses.
- Known limits: there is no browser page; one tool's memory database and the instruction files are counted, not imported; secrets with no recognizable shape (a bare password in prose) cannot be caught by redaction or the HOLD stage, so read the dry run.
- What the importer prints, and the reports, samples files, project-map drafts and self-test result it writes, pass a filter that replaces a string carrying a recognised secret with an index label such as `bank#3`; the command line has its own filter for its output, `--json` and forwarded output. Source-tree lint tests and command-matrix tests (recognised secrets placed in bank, folder, label, file, project-key and error positions) check it. The ledger, the state file and backup names keep real names; see the README's known limits. Backup exemptions are decided on all content kinds a bank can hold and fail closed. After a failed embedding step `setup` removes only its own token and the empty folders it created, each re-checked first.
- Known residual risks: a link made between the symlink check and the library's own open; open-bank detection cannot exclude a process that opens a bank between the check and the write; `bun add` runs install scripts of trusted packages with your whole environment.
